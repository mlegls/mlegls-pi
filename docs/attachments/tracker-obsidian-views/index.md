# Tracker Bases first-use drive

## Predictions before opening the product

Source: ticket and `extensions/obsidian-tracker/FIRST-USE.md` only. Persona: new user of a disposable desktop Obsidian vault, no credentials.

- **First use:** Opening `/tmp/tracker-obsidian-views-clean/Tracker.base` should show a functioning Base with saved Tree, Board, Network and six legacy modes after plugin trust. I should be able to switch views without configuration.
- **Tree:** Parent, open/done children, external blocker and isolated issue should be visible according to Base entries. A parent should show its own stage, subtree stage, and 1/2 subissue completion even if a child is filtered. Clicking collapse should hide descendants; switching view or navigating away/back should retain collapse. Clicking a link should open its issue, command-hover should preview, and context menu should offer copy/open-in-pane/file operations.
- **Board:** Columns should reflect arbitrary `lane` grouping, not workflow stages; cards should sort by descending filename. Filtered Board should show only parent while retaining 1/2 completion and external blocker. Card links should expose the same native operations and hover as Tree; no stage-change drag/drop expected.
- **Network:** Connected parent/children and isolated issue should be presented, isolated node labeled on hover. Clicking opens issues, command-hover previews, context menu offers native link/file operations. Dragging a node pins it; navigation away/back retains the pin; double-click unpins without opening the issue.
- **Other modes:** Frontier, Mine, Done, Invalid, Legacy and All should remain selectable and render appropriate entries rather than unknown-view errors.

### Expectations and frictions

- **Met:** Entry opened working Tree without another trust prompt on inherited trusted state; ten modes; Tree subtree and blocker; arbitrary lane grouping, descending Board sort, filtered 1/2 rollup; isolated-node hover label; collapse and pin persistence; clicks to notes.
- **Not established:** Command-hover preview, right-click Copy link/file menu/open-in-pane on all three surfaces. Native right-click attempts on Tree and Network produced no reliably captured menu. A Tree anchor received `contextmenu` (capture listener), and later a bubbling listener recorded `defaultPrevented: true`, so this does *not* establish a product defect. Don't infer native operations from `internal-link` markup. Full per-mode membership also unobserved.
- **Friction:** `own done · tree ticket` looks contradictory until one understands own vs subtree. `p?` is unexplained in the UI. Board's Outside column clips at this viewport and requires horizontal scrolling. Done rows are so dim they look disabled. Returning to Base selects Tree, not the previously selected Network (pin itself stays). Async renderer updates can mislead fast interactions. Native computer's semantic capture missed Base controls entirely.

## Review

Reviewer drive on `6bbea97`, in an owned Obsidian 1.13.7 instance (separate `HOME` and profile, 1024×800, no credentials) over a fresh `first-use.sh /tmp/tracker-obsidian-views-review-1` vault. A parallel worker's Obsidian instance had taken `~/.obsidian-cli.sock`, so the shared instance was unreachable by CLI: [issue](../../issues/obsidian-cli-socket-taken-by-parallel-instance.md). `nativeMenus` was turned off in this vault so menus appear in the DOM; the menu contents are the same with native menus.

Why the driver saw no menu: on macOS Obsidian draws context menus natively, outside the DOM. Once the menus were visible, they showed the tracker's own "Open in new tab / Open to the right" items plus a `file-menu` fired with source `tracker`, which dropped **Rename…** and any plugin items that target link menus. Repaired: `fileMenu` now builds on `workspace.handleLinkContextMenu` (Obsidian's link menu) and adds Copy link / Copy Obsidian URL.

1. **Native operations: held on all three surfaces.** Right-clicking the `parent` Tree link, Board card link and Network node each gave: Open in new tab, Open to the right, Open in new window, Rename…, Move file to…, Bookmark…, Copy path, Open in default app, Reveal in Finder, Reveal file in navigation, Copy link, Copy Obsidian URL ([tree](14-review-tree-menu.png), [board](15-review-board-menu.png), [network](16-review-network-menu.png)). On each surface Copy link put `[[parent]]` on the clipboard, Copy Obsidian URL put `obsidian://open?vault=tracker-obsidian-views-review-1&file=projects%2Ftracker-demo%2Fissues%2Fparent.md` there, and Open to the right opened `projects/tracker-demo/issues/parent.md` in a second pane while the Base stayed open. Cmd-hover showed a preview of the Parent note on all three while `Tracker.base` stayed active ([network preview](17-review-network-preview.png)). A Network preview appears only when the pointer is on the node's circle. It also does not reappear if a script removes the popover DOM without hiding it; that is a probe artifact, not a product defect.
2. **Legacy modes: held.** After waiting for each view to settle: Frontier `isolated`; Mine `dependency`; Done `child-done`; Invalid `invalid`; Legacy `legacy`; All the six non-legacy issues. Each list is identical to `model()` over the committed fixture and matches the lifecycle (child-open is blocked by `dependency`; parent is own done).
3. **Board width: repaired.** Columns now shrink to 180–360px before scrolling; all three lanes fit the 665px pane with no horizontal overflow ([board](13-review-board-fit.png), replacing the clipped [03](03-board.png)).
4. **Re-driven after the repairs:** Filtered board still shows only `parent` in Delivery. Tree collapse survives Board→Tree and a note→Base round trip, and re-expanding restores the children. The badge now reads `own stage · subtree stage` on hover and `p?` reads `priority unset`. Pin persistence code is unchanged since the driver's run.

Frictions sorted: Board clipping fixed; own/tree and `p?` got hover titles, with dim done rows and the reopen-selects-Tree behaviour filed as [row legibility](../../issues/tracker-obsidian-row-legibility.md); driver's native-computer friction is already [filed](../../issues/computer-obsidian-base-semantic-drive.md). The ticket asks for no new permanent tests, so the replayable checks remain in this packet and `FIRST-USE.md` (which now notes the `nativeMenus` and hover-coordinate caveats) rather than in the suite.
