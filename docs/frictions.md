# Frictions

- `exec` moves operations below pi's tool-event boundary. Inner `read`/`sh` calls do not fire individual tool events, but outer tool-result middleware can still rewrite their displayed output. During dogfooding, pi-better-skills interpreted an anchored SKILL.md shell block as a command containing line numbers and anchors and reported `command not found`. The source snapshot remains raw; the displayed text is not guaranteed to be. An explicit skill-loading capability or exec-aware middleware would separate raw source from executable skill expansion. Next: simplify.
- `exec` tagged templates cross JSON, TypeScript, and source/shell escaping layers. Both `edit` and `sh` consume cooked strings: a source `\n` became a newline, and nested shell regex/JavaScript escapes broke commands during dogfooding. Embedded backticks and `${...}` also need protection. Source selections plus `replace`, `grep` with RegExp literals, and direct module imports avoid some layers; raw tags or a clearer construction idiom would reduce the remaining cognitive load. Next: simplify.

- Structured service results expose inconsistent vocabulary: `wm.status()` calls a handle `worktree`, which required an extra discovery step in live dogfooding; the API reference now names the mapping. Removing a quiet board subscription also returned the irrelevant default `wake:true`, although removal succeeded. A board read also accepted an invalid array tag filter far enough to fail with `source.trim`; reads expect a tag-expression string while sends take a tag array. Clearer service-facing records, argument validation, and discoverable schemas would reduce these interpretation costs. Next: simplify.
- Desktop integration has a tool-only upstream API: exec captures the public extension factory and journals result details because upstream restoration scans named tool-result messages. This couples the adapter to upstream result metadata and lifecycle behavior. A host-call/state-restoration API upstream would remove the projection; the adapter preserves existing behavior without maintaining a fork. Next: simplify.
- Native UI discovery can expose unlabeled controls only through refs/subroles: live search for a Close button by role and text returned no match, while inspection of its known ref worked. Role-only search is a workaround; subrole-aware search belongs upstream. Whole UI details also duplicate the outline; select capture metadata rather than printing all details. Next: simplify.
- Exec operation previews are a separate display path from explicit show output: reusing arbitrary render/content methods could trigger side effects, expose private image payloads, or do unbounded work. Known source/shell results receive bounded passive formatters; other results use descriptor-only previews. This duplicates some presentation logic, and returned source-selection methods are deliberately not instrumented. A shared passive display protocol could reduce the duplication. Next: simplify.
- Worktree verification required more than installing root dependencies: outline-read and disabled LSP tests resolve nested node_modules that were absent in fresh worktrees. Temporary links to the primary checkout unblocked checks, then were removed. A reproducible worktree dependency setup would eliminate this repeated discovery. Next: simplify.
