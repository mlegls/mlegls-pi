## Closed read contract

1. Resolve the canonical project using `checkout(cwd).project`, not the linked worktree's physical files or common-dir parent. A canonical `docs/issues/` wins in the eventual selector. `getGithubTracker` returns undefined only when `docs/agents/issue-tracker.md` does not select GitHub; a selected but malformed configuration or unavailable API throws. Resolve one exact GitHub repository from its project convention/remotes; never silently use a different host/repository. No external repository can become `gh-<n>` in this run.
2. Read the repository's `docs/agents/triage-labels.md`. Deployed table header is `| Label in mattpocock/skills | Label in our tracker | Meaning |`: first column canonical role, second configured label (backtick-wrapped cells), third prose. Roles are needs-triage, needs-info, ready-for-agent, ready-for-human, wontfix. Configured label strings are not hard-coded. Missing required role mapping or contradictory triage states is a diagnostic, not agent readiness. A configured label absent from the current GitHub inventory need not break unrelated reads (webapp currently lacks needs-triage).
3. On unmodified convention issues: ready-for-agent root/standalone leaf enters as spec; a ready-for-agent parent with sub-issues is a partitioned spec, and its ready-for-agent leaf sub-issues are tickets. A sub-issue with its own children is again a spec. `wayfinder:map` and `wayfinder:research|prototype|grilling|task` express map/type, not `stage:*` or model routing. ready-for-human is human-owned, never agent-eligible; other/untriaged roles do not become executable. CLOSED means globally done. Inference remains subordinate to current native triage/state: private receipts cannot make an issue whose ready label was removed executable.
4. Normalize identities/relations to `gh-<positive number>`. Read native parent/subIssues and blockedBy; only recognize the convention's anchored `Part of #n` / `Blocked by: #n, #n` fallback headers when native relations are unavailable/absent. Casual mentions are not edges. Keep native repository identity on relations: an unresolved foreign blocker remains an opaque guard, never aliases a same-number local issue. Closed blockers are resolved even though GraphQL blockedBy includes them. Validate graph cycles/completeness before projecting lifecycle rollups, own claims, selectors, frontier and effective stages.
5. Native assignees are published claims, not logical routing selectors. Logical assignee comes from the mapped triage role plus any adapter-authored stance metadata. An assignee with no exact matching durable local ownership receipt is foreign, including the authenticated user; do not infer ownership from @me. The following writes child supplies backend-private run receipts under the repository's git-common reconcile state, with exact stable/attempt tokens and explicit promotion/delegation. Leave a clear private seam for that reader: no receipt = convention inference; explicit `stage: ticket` promotion and omitted residual (`stage: null` update) must be distinguishable from no override. No stage:spec label. The backend's private serialization may be completed serially by the writes child; no consumer outside this adapter depends on it.
6. `fields` returns normalized logical fields and preserves adapter-authored extra metadata; `text` returns the title, metadata, full Markdown body and every comment in chronological order with attribution. Keep comments inside the synthesized frontmatter (for example a read-only comments field), ahead of the native Markdown body, so the existing `text(...).replace(frontmatter, '')` round-trip does not copy comments into the native body. Do not fetch/parse OpenSpec or arbitrary linked documents. `githubIssue` returns the exact same-repository native number/repository/URL.

## Snapshot transport and cache

One named GraphQL operation `TrackerSnapshot` per actual refresh; include repository identity/id, viewer login/id, labels, issue bodies/state/stateReason/title, parent/subIssues, blockedBy, assignees and comments. Use GitHub's ordinary authenticated `gh api graphql`; bound process time and response size; GraphQL errors/partial data never mean an empty graph. No per-issue REST fan-out. `text`, `fields`, scope filtering and repeated scheduling reads reuse the same snapshot.

Cache for about 60 seconds across the run's ticks and across its worktrees/CLI processes, under the git common dir, with a crash-released interprocess lock and atomic publication. All adapter writes will invalidate the cache across processes. Do not tie freshness to code HEAD. Return isolated projections, not mutable aliases of cached state.

Live schema limits connections to 100. webapp currently has 182 issues across all states. In the single operation request both first:100 and last:100 repository issue pages, deduplicate by node ID, and do the analogous coverage/completeness accounting for nested connections when needed. Require unique node count = totalCount for every required connection; overlapping aliases are not a second network query. Never publish a truncated snapshot. If the one-request query plan cannot cover a connection, fail closed with the exact connection/count and an actionable diagnostic instead of issuing an unrecorded extra refresh query. This ticket must actually cover today's 182-issue webapp, not stop at 100. No unbounded-repository claim is made by this fixed-page first implementation.
