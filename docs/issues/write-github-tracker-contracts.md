## Closed mutation contract

1. `create({slug, fields, body})` returns the actual `gh-<number>`, not the requested slug/title. `fields`/`update` use logical gh identities for relations, guards stay opaque, extra metadata survives, explicit author or PI_SESSION_ID supplies immutable provenance. A requested title may be supplied in fields; otherwise use the requested slug as title. Omitted body preserves it; supplied body, including empty string, replaces only the whole native Markdown body, never comments. Null removes a named logical field. Preserve unrelated labels, user body, comments and assignees.
2. Map ready agent/human roles through the local triage table; map `drive: none` to `no-drive`. Use native sub-issues for part-of and native dependencies for blocked-by. REST relationship writes take numeric database IDs, not issue numbers or GraphQL IDs. The convention fallback is an anchored `Part of #n` / `Blocked by: #n, #n` header (and the map's child list when required by its documented fallback). Use fallback only for a positively unsupported native capability under the repo convention; permission failures, timeouts, rate limits and arbitrary 4xx/5xx are not permission to publish a different graph. Validate requested same-repo relations/graph and supported field values before writes; report a partial remote mutation honestly and retain replay intent.
3. Run ownership is native assignment to the authenticated user plus an exact backend-private receipt in that repository's git-common reconciler state. Use a backend-owned companion beside the run JSON (for example `<common>/reconcile/<root>.github.json`) so a worker's write cannot be lost when the reconciler saves its in-memory main state. Serialize cross-process receipt writes/cache invalidation with a crash-released lock and atomic replace. Record the exact repository in each receipt. Explicit options.run, otherwise PI_WM_RUN, selects a run only after checking its saved run/attempt authority. `reconcile:<root>` and `reconcile:<root>/<handle>` are distinct tokens, never prefix authority. A same-login native assignee without the matching receipt is foreign; refuse stealing it. Removing a claim may remove only the assignment this run owns, never somebody else's assignment.
4. Store explicit stage promotion/delegation durably without stage labels. No override means infer the convention; explicit stage ticket and omitted residual stage after a `stage: null` update are different states. Keep these backend-private receipts readable across worker/CLI/reconciler processes and restart; they never override a current human/not-ready triage role or CLOSED state. Ordinary extra logical fields/provenance/stance selectors may use a namespaced hidden body metadata envelope, preserving user Markdown and stripping generated metadata from the contract body returned for replacement. Never put run/attempt claim tokens in labels, issue bodies or comments: which run owns it stays private. Standalone non-run field writes still round-trip through backend metadata; no phantom ownership is inferred.
5. For a provisional create, atomically supply the parent and native assignee in GraphQL `createIssue` (`parentIssueId` and `assigneeIds` coexist; schema-verified 2026-10-15). Use repositoryId/parentIssueId/assigneeIds/labelIds as GraphQL node IDs. Persist a creation intent containing the exact attempt token before publishing; include a unique opaque correlation marker in the generated body metadata, not the claim token. Thus a lost response/process death is recoverable by the snapshot: the issue is already assigned and parented, and the pending intent recovers its exact ownership without guessing by title. A replay must discover the same remote child, not create another. The public snapshot/fields must never expose that child as an unclaimed executable contract between create and ownership receipt. `clientMutationId` alone is not a server-side idempotency guarantee.
6. The existing refinement protocol must work unchanged through Tracker: discover a crash-adjacent create, transfer only the exact owned claim on adoption, convert to stable reservation after committed stubs land, and discard only still-owned provisional descendants. `remove` is close-as-NOT_PLANNED, never admin deletion. Detach the removed child's parent and its own blocker relations/claim (or an equivalent removed projection) so the existing discard loop cannot see a retained closed dependent/child forever. Removed provisional identities are absent from the executable graph and from future refinement child counts, while their native not-planned outcome remains inspectable. Do not close/detach a baseline, adopted-away or foreign-owned issue. Interrupted remove is replayable.
7. `close` posts the supplied summary and evidence once, closes as completed if still open, clears the owned claim and resolved same-repository dependency/fallback edges on dependents, and replays remaining work after partial failure. GitHub may already have auto-closed it from a merged PR's Closes line: still publish the saved reviewed result, do not reopen, and do not skip evidence merely because state=CLOSED. Use a stable result marker to avoid duplicate comments across response loss/restart. The caller owns proof of target landing; this adapter does not close on collector integration.
8. Evidence normally links the committed `docs/attachments/...` path to an exact published Git commit, not a local absolute path or an unpinned branch name. If the repository's tracker document explicitly declines attachments, put the evidence content in the closing comment instead; do not infer decline merely from an observed alternate directory. `moveOut(slug, reason)` removes the mapped ready-for-agent role, adds mapped ready-for-human, posts the reason idempotently and releases only this run's assignment/claim. It does not silently edit somebody else's routing or scope. Existing owner-edited relation changes remain the move-out protocol outside this hook.
9. Invalidate the repository's shared snapshot cache after every successful adapter write and after any uncertain partial write; next successful snapshot refresh is still one `TrackerSnapshot` operation. Logical private receipt changes are also visible immediately to fields/snapshot without waiting a minute.
