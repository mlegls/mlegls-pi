## Edits

- Keep Worker/Outcome, prompt/common/role/stance composition, fork/summary provenance, next/events/done/wait and abort/unread/report-race behavior. Handle and topic remain run/handle, branch is recorded owning branch, dir is record.cwd/worktree, and canonical pi session identity is separate from thread id. Add Worker.threadId and include it in toJSON; the legacy `session` spawn/attach parameter is tolerated but no longer creates a grouped terminal session. `attach(run,handle,cwd,…)` resolves the unique registered worker lazily rather than guessing a worktree path or window.
- `spawn` invokes newThread/forkThread with worker identity, handle as worktree name, supplied base, cwd as integration/spawning checkout, routed model/thinking args, composed prompt and spawnEnv. Preserve “command OR model/effort” validation and `--approve`. A fork is materialized once by the registry and all restarts resume the allocated session. Summary prepending is unchanged. Register board observation before launch so a very fast report is not lost.
- Replace workmux status/tmux pane sampling with threadSnapshot/listThreads + readLive + board. A gone .agent zmx session or observed canonical pi pid is exited. Respect startup grace before the first pi/live record; reattached workers get bounded current-state observation, not indefinite spawn grace. A restarting pi does not turn the board's done into archival/cleanup; its next turn is still awaitable. Unknown/backend observation errors defer and surface, never fabricate exit. Normal pi idle/no-status comes from board turn-end; explicit non-pi command fixtures may use terminal liveness/history without a fake pi record. Keep one event per quiet turn and report precedence.
- `send` delegates literal bytes to sendThread with no CR; `capture(lines)` delegates historyThread. `status` returns live working/idle or gone as existing callers need, not workmux's done/waiting vocabulary. `close(keepBranch)` delegates abandonThread; idempotently detach from polling after successful close. `exec` executes argv in recorded cwd using the existing sh helper, not a workmux command. The exported wm.merge wrapper delegates integrateThread and translates conflicts to existing wm.MergeConflict. Remove the workmuxStatus export/calls from this module; remove its other imports in the same cutover.
- `childSession` uses workerThread's current sessionFile. Keep signature so /jump callers don't change; do not choose a newer free session or a stale pre-/new file.
- Session-meta adds `thread?: string` to SpawnMeta and Live, obtained from validated canonical registry membership (or the matching AB_THREAD_ID at first launch); regular threads and pi resumed by hand must join. Preserve worker/invokedBy provenance and board subscription snapshots. A pi outside any thread remains untracked. Existing worker env names may stay as compatibility provenance, not transport selection. Session_switch/updateSession belongs to [[projects/mlegls-pi/issues/thread-commands-in-pi]].
- Board agent_end still publishes workers to PI_BOARD_TOPIC. For an ordinary canonical thread without that env (including promotion/by-hand resume), resolve membership and publish its terminal report to thread/<id>. This is necessary for archive conflicts, not a new mailbox API. Free sessions retain current no-auto-report behavior. Don't remove @mailbox/TMUX_PANE handling yet; [[projects/mlegls-pi/issues/delete-workmux-and-tmux-paths]] owns that deletion.
- Keep lib/tree/graph.ts's consumer join to the sidebar sibling: publish the thread/session-meta field. No tmux UI migration here.

## Dispatch/reconciler edits

- Receipts and persisted Handle gain optional threadId; dispatch supplies it from Worker. Keep handle/run/path/cursor semantics, validation-before-launch, capacity, follow decisions, tracker ledger and no implicit retry. Add optional threadId in the supervision tool HandleSchema; accept legacy session data but never use it to create/select a tmux transport. Bare handles resolve through workerThread in the requested cwd's project; structured receipts use their record/path, not guessed workmux layout/status.
- Integrate delegates the raw integrateThread primitive (default rebase, explicit merge). It merges into the record branch's ab-parent, not caller HEAD; the normal dispatcher branch was stored at spawn, so the ordinary workflow stays the same. Preserve keep, prepare and public Integration result and translate ThreadMergeConflict to dispatch.MergeConflict for the extension/reconciler's existing conflict handoff. Raw integrate does not automatically message/archive the subtree; this supervisor already controls retries/acceptance.
- Retire delegates worker.close(true)/abandon retirement, then deletes the owned branch only when every patch is in ab-parent (`git cherry`, including rebase-equivalent patches), retaining/reporting unmerged or checked-out branches. Guest/shared checkouts cannot be removed or swept for leftovers. Centralize the cwd/zmx cleanup in lifecycle; don't keep a second lsof/workmux cleanup in dispatch. The archived worker's record may be needed to resolve its branch/parent after its path disappears. Preserve cleanup-after-successful-integration ordering.
- children retains run/handle IDs, mailbox sends, after cursors, waitForTurnEnd's board-only recovery and unreachable-on-exit behavior. Its deliberate follow-up submission appends a real CR because the new Worker.send is literal; do not submit before it has all text. Synthetic wm exit cursors already stored on disk remain readable. A closed worker does not spin on the same old report; observer teardown still drops polling.
- Reconciler replaces workmuxStatus/tmux panes/alive with batched current registry/zmx/live observations of registered worker threads. Preserve startup grace, report freshness, budgets, exception handler ownership, phase gates and evidence acceptance. No tmux run-session setup/final kill. No workmux calls or pane heuristics.
- Crucial launch seam: base SHA and integration destination are not the same field. Pass the actual destination checkout to dispatch so every worker branch stores that checkout's branch as ab-parent. startPhase uses pathOf(c.into); exception handlers use their ancestor collector; a node's residual worker may start from collector HEAD but still integrates into its own parent checkout. Owner root uses the owning checkout from o.cwd, not an accidental canonical-main branch selected by repoRoot. Git-common-dir still locates shared locks/state. Collector worktrees are git aggregation artifacts without a canonical pi, not active threads; preserve their lifecycle but explicitly record their parent-branch lineage rather than treating base SHA as a destination.
- Persisted new runs/reattach use thread identity. Pre-cutover workmux reconcilers drain with their old code; do not add a dual-backend fallback or migrate their active state/resources here. [[projects/mlegls-pi/issues/delete-workmux-and-tmux-paths]] owns namespace/docs wording cleanup; change tool schema/behavior needed for new receipts, not its broad prose sweep.
