## Prototype UX while shaping

A change to what learners or I see is drawn with me while we shape it, not when a worker reaches it. The grilling session draws it on the project's canvas—or spawns a top-level sibling thread to draw while we keep talking—and I annotate until it's right. The issue links the approved screens before becoming ready; workers wire behavior behind screens I've already seen. A worker who hits an unanswered UX question sends the node back to shaping instead of filling `desk/ATTENTION.md` with concurrent in-flight drawings.

Source, 2026-11-04: "It seems the current de facto process is to make UX drawings just in time for implementation and present them to me in attention.md from the main supervision thread, and this is creating a lot of chaos. I'd rather it be that anything that would make UX changes does the prototyping interactively with me during planning, either in the same session or a sibling session from the grilling session". At the time, five of concept's six attention items were worker drawings in flight (masthead, band progress, share image, graph ground, Mission-centred runs).

Implementation: the `shape`, `supervise` and `implement` skills; concept's `docs/design/screens.md`.
