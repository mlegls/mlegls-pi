---
name: writing-shape
description: "Use when outlining an article from raw material."
disable-model-invocation: true
---

The user passes a markdown file of raw material — any format. Read it end-to-end first. This is **exploit**: the pile is fixed; commit to a structure and mine the pile to fill it. The raw file is read-only. If no article path was given, ask once and remember it.

1. **Establish prerequisites**: settle with the user which concepts are **grounded** walking in (see Grounding).
2. **Draft 2–3 candidate openings**, each implying a different thesis. Force a pick or a hybrid; the opening defines what the rest must do.
3. **Grow block by block**: "given this opening, what does the reader need to hear next?" — pull from the pile to answer, argue the block's form out loud (prose vs list, inline vs callout, table, quote, code), append each agreed block to the file immediately. Loop until the user says done.

**Grounding**: every concept must be grounded — a prerequisite the reader brings, or introduced by an earlier block — before a block leans on it. The unit is the concept, not the word: a block can lean on a missing idea with no jargon in sight; where a concept has a term, ground idea and term together. Keep a running grounded list. An ungrounded concept the next move needs *is* the answer to "what next": ground it, or promote it to a prerequisite. Too many prerequisites shuts readers out; grounding everything inline drowns the opening in definitions — settle the balance with the user.

This is a grilling session inverted: "what is this article arguing, and in what order does the reader need it?" Push back — "if I cut this, what breaks?", "the opening promised X, we've drifted to Y". Treat the pile as a quarry: split, merge, paraphrase fragments; the article reads as one voice. If the pile lacks something the article needs, name the gap: "give me an example now or we cut this section."

Rhythm: re-read the file from disk before every write (the user may have edited); never overwrite blindly; rewrite requests edit that block in place.

Out of scope: mining new fragments, editing the raw file, publishing/platform formatting/unasked frontmatter.
