name: writing-fragments
description: "Use when exploring raw material for a piece of writing before structuring it."
disable-model-invocation: true
---

Pure **explore**: widen what could be written without committing to structure (committing is _exploit_, a separate skill's job). Run a grilling session that produces **fragments**, appending them to a single markdown file as they emerge from either side of the conversation — starting with the user's very first prompt. No phases, outlines, or article structure.

If no path was given, ask once where to save, then remember it.

A fragment is anything that might survive into the final article — readable by the author, not necessarily by a cold reader: a sharp sentence, a claim with one-line justification, a vignette, a half-thought, a quote, a cluster of observations, a complaint, a punchline. The most valuable is a **leading word**: a compact metaphor or coinage the whole piece can hang on (the way _tracer bullets_ names a whole pattern) — it shapes structure, transitions, and title through the entire exploit phase. When the conversation circles a recurring idea, push to coin a word for it.

File format: a single H1 working title on first write (nothing else — no metadata, TOC, or date), fragments separated by `\n---\n`, no headings inside bodies, no tags, in the order added.

Rhythm: append silently ("adding that" in passing, no save dialogs). Re-read the file from disk before every write — preserve the user's edits absolutely; only append, never overwrite. "Cut the last one" / "rewrite that sharper" / "merge those two" are first-class instructions.
