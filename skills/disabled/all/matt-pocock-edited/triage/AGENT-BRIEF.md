# Agent brief

A triage brief is a small spec, not another requirements system. It carries the
maintainer's decision into unattended work; original reports and discussion
remain linked context.

Record the present and desired behavior, the settled Shape and its reasons,
acceptance evidence, and any consequential open questions or exclusions. Use
story IDs where the argument already exists (`stories`, `to-spec`). Source
paths and symbols are useful pointers, not permanent assumptions about layout.

For a PR, describe what remains to do to the contributed change. The agent is
finishing or correcting that diff, not rebuilding the feature from a blank
page. A brief can be a few paragraphs when that is enough to work fresh.
