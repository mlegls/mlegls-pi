description: "Use when arranging writing fragments into a sequence of beats."

The user passes a markdown file of raw material. This is **exploit**: the pile is fixed; mine it to fill each beat. If no article path was given, ask once and remember it.

A **beat** is one move — sets a scene, lands a point, asks a question, twists the angle — sized from one sentence to a few paragraphs; a beat needing five paragraphs and subheadings is two beats glued together. The article ends when the journey completes, not when the pile is empty; leftover fragments are the point of having more material than you need.

Run it choose-your-own-adventure style:

1. Settle the **prerequisites** with the user: the concepts **grounded** walking in. Every other concept must be grounded by a beat before a later beat leans on it — the unit is the concept, not the word; where it has a term, ground idea and term together. Keep a running grounded list. A tempting beat requiring an ungrounded concept means: a grounding beat first, or promote to prerequisite (too many prerequisites shuts readers out; too much grounding drowns the early beats).
2. Offer 2–3 candidate **starting beats** from the pile — shown before writing to the file, each noting what it grounds — and preview what the pick unlocks: a candidate is only reachable if everything it requires is grounded, and picking one that grounds X unlocks every beat waiting on X.
3. Write **only the picked beat** to the file. Stop.
4. Re-read the file from disk, then offer 2–3 reachable **next beats**, noting what each grounds.
5. Loop 3–4 to a natural end.

Rhythm: one beat at a time, never ahead; re-read from disk before every write and preserve user edits absolutely; a substantially edited beat changes what comes next; "rewrite beat 3" edits in place, leaving the rest alone.
