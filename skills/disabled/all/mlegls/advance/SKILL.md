name: advance
description: "Use when continuing tracked work or choosing the next item in a project or scope."
disable-model-invocation: true
argument-hint: "a map, issue, area, type label, or nothing"
---

The frontier is work that can usefully move now, not the whole backlog.
Read the scope's map and run the frontier query in the project's tracker docs.
For project-wide work, include `difficult` issues and open theory hypotheses.

1. For a named item, orient to its destination and latest discussion. Otherwise
   show the live choices by title, what each resolves, and what it unblocks.
   Recommend a next move and confirm the intended work and tracker changes
   (`grilling`), unless this batch is already approved.
2. Claim the selected work using the tracker's convention. Recheck ownership
   and blockers before writing; other sessions may be working nearby.
3. Fill the question or implement the ticket. The fill method points to
   `grilling`, `research`, `prototype`, `wizard`, or `implement`.
4. Show the answer and resulting tracker changes for confirmation before
   publishing, unless covered by the agreed publication policy. Then record the
   answer on the item and its gist on the map, updating affected dependencies.

Continue while another useful move fits the mandate. A session boundary is not
inherent in a hole; independent research can proceed alongside the main work.
